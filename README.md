# 네오 아보카도

[AvocadoEdition](https://github.com/tateck-develop/AvocadoEdition)(그누보드 5 기반
자캐 커뮤니티)을 나루 SDK 1.1.0으로 옮긴 사이트입니다. 원본의 어떤 기능을 어떻게
옮겼는지, 무엇을 옮기지 않았는지는 [docs/porting.md](docs/porting.md)에 있습니다.

## 처음 설치하기

**필요한 것**: 사이트 데이터베이스는 나루 서포터 플랜에 포함되어 있습니다.
회원으로 로그인하는 사람도 서포터 플랜이 있어야 하며, 예외가 필요한 커뮤니티는
나루 운영자에게 문의해 주세요.

1. **사이트에 설치합니다.** 둘 중 하나를 고르세요.
   - 나루 게시판의 네오 아보카도 템플릿에서 **적용하기**를 누르고, 적용할 폴더를
     **사이트 맨 위(루트)**로 고릅니다. 서버 함수가 들어 있는 `_naru/` 폴더는
     사이트 맨 위에 있어야 동작하므로, 하위 폴더에 적용하면 회원 기능이 켜지지
     않습니다.
   - 또는 이 저장소를 내 GitHub로 가져가 나루의 GitHub 배포를 사이트 맨 위에
     연결합니다. 이후 푸시할 때마다 사이트가 갱신됩니다.
2. **컬렉션은 파일과 함께 준비됩니다.** `_naru/collections.json`이 이 사이트에
   필요한 컬렉션과 권한을 선언하고, 나루는 파일이 올라오는 순간 없는 컬렉션을
   만듭니다: 로그·댓글은 `community-board` 규칙과 함께 회원(공개 게시판은
   손님도)이 읽고, 캐릭터는 `characters` 규칙이 볼 수 있는 항목만 회원과
   (사이트공개 중에는) 손님에게 보여 주며, 프로필은 닉네임 중복 금지, 나머지는
   관리자만 읽고 씁니다. 이미 있는 컬렉션의 설정을 바꿔야 하면(예: 손님이
   멤버목록을 보도록 캐릭터·추가 항목·소속·종족·타이틀·관계·옷장·커플을 ‘누구나
   읽기’로 바꾼 것) 나루의 데이터베이스 화면에 표시되고, 확인한 뒤 적용하기를
   누르면 바뀝니다. 그다음 `admin/`(운영 화면)에서 운영자 로그인을
   누릅니다.
3. **가입 방식을 정합니다.** 나루의 데이터베이스 → 사이트 회원에서 누구나 가입,
   운영자 승인 후 이용, 신규 가입 중단 중 하나를 고르고, 필요하면 이메일을
   인증한 계정만 받도록 합니다.
4. **운영 화면에서 커뮤니티를 꾸밉니다.** 게시판(예: 자유, 공지)과 등급,
   캐릭터 추가 항목, 디자인과 메뉴, 안내 페이지를 만듭니다. 원본처럼 처음에는
   게시판이 없으니, 로그를 올릴 게시판부터 만드세요(게시판을 지정하지 않은 글은
   ID `default` 게시판에 속합니다). 사이트 전체 설정은 **커뮤니티 설정** 한 화면에 있습니다.
   운영 화면의 왼쪽 메뉴는 원본처럼 환경설정·회원관리·게시판관리·캐릭터관리·아이템
   관리·기타관리로 묶여 있습니다.

화폐(기본 `아보`), 경험치, 랭킹, 소속, 종족의 이름은 원본의 **기타 항목명 설정**처럼
커뮤니티 설정에서 바꿉니다. 바꾼 이름은 사이트와 운영 화면, 서버의 안내 문구에 모두
쓰이고, 소속이나 종족의 이름을 비우면 프로필과 운영 메뉴에서 그 항목이 빠집니다.

개발할 때는:

- 검사: `npm test`, `npm run lint`
- 로컬 나루(naru-dev)에서 실제 Chromium으로 전체 흐름:
  `NARU_REPO_PATH=… PLAYWRIGHT_MODULE=… npm run test:e2e`
- 직접 써 보기: 나루 저장소의 `control-plane/`에서
  `pnpm naru-dev ~/Git/neo-avocado --site neo-avocado` 후 http://localhost:4000

## 손님과 공개 게시판

그누보드처럼 등급 1은 로그인하지 않은 손님입니다. 게시판의 목록·본문 등급을
1로 두면 누구나 읽고, 글쓰기·댓글 등급을 1로 두면 손님이 이름과 비밀번호로
씁니다. 손님 글은 그 비밀번호로만 고치고 지웁니다. 손님은 비밀글, 캐릭터,
탐색·아이템, 호출, 파일 올리기를 쓸 수 없고 그림은 HTTPS 주소로 넣습니다.
비밀번호는 나루가 글의 쓰기 비밀(secret)로 PBKDF2 해시만 보관하며, 아무도 읽을 수
없습니다. 읽기 등급이 1인 안내 페이지도 공개됩니다.

**커뮤니티 설정**의 **사이트공개**(원본 `cf_open`)가 켜져 있으면 손님도
멤버목록, 신청자목록, 커플목록과 캐릭터 보기(`#/character/캐릭터ID`)를 볼 수 있고,
캐릭터의 추가 항목은 공개 항목만 보입니다. 끄면 손님에게는 인사말과 회원
로그인 카드만 보이고, 게시판·글·캐릭터·닉네임도 규칙이 읽어 주지 않습니다(원본은
모든 페이지에서 손님을 로그인 페이지로 보냅니다). 원본은 설치 직후 꺼져
있지만, 여기서는 지금까지처럼 손님이 볼 수 있도록 켜진 채로 시작합니다.

## 게시판

로그마다 게시판별 번호(No.)가 붙고, 본문의 `@번호`는 그 로그를, `#태그`는
같은 태그의 로그를 엽니다. 모더레이터는 로그를 공지로 올리거나 다른
게시판으로 옮깁니다. 게시판 설정의 **HTML 본문 허용**을 켜면 최대 12,000자의
HTML 글을 쓰며, 스크립트·폼·스타일은 표시하지 않습니다. 게시판의 **행동 허용**을
켜면 원본처럼 글에서 **조합**(재료 1~3개, 레시피와 맞으면 제작, 틀리면 재료만
소모)과 아이템 사용을, 댓글에서 탐색과 아이템 사용을 합니다.

그림 로그를 쓸 때는 원본 mmb 스킨의 옵션을 고릅니다. **멤버공개**는 손님에게
번호와 표시만 보이고 본문·그림·댓글은 잠기며, **19금**은 빨간 표시와 함께 그림을
가렸다가 누르면 보여 주고, **리플창 아래로**는 댓글을 그림 아래에 두고,
**로그접기**는 그림을 접어 두었다가 OPEN으로 펼칩니다. 게시판의 **로그 자동 접기
높이**보다 큰 그림은 저절로 접힙니다. 게시판에서 **익명 사용**을 켜면 회원은 글과
댓글을 익명으로 쓸 수 있고, 다른 회원과 손님에게는 ‘익명의 누군가’로만
보입니다(작성자 본인과 운영진은 누가 썼는지 봅니다). 멤버공개·19금·익명은
회원만 고릅니다. 댓글은 여러 줄로 2,000자까지 쓰고, 단 시각이
초까지 붙습니다.

## 메뉴·디자인·메인 슬라이드

기본 화면은 원본 아보카도 에디션을 설치한 직후(디자인 사용 꺼짐)와 같습니다:
흰 바탕, 왼쪽 위 로고, 가운데 세로 메뉴, 메인의 검은 슬라이드 띠와 회원 카드,
TOP 버튼. 원본과 달리 휴대폰에서는 메뉴가 버튼 뒤로 접히고 상자가 세로로
쌓입니다. 오른쪽 위의 화면 모드(시스템·라이트·다크)로 방문자가 어두운 화면을
고를 수 있고, 고르지 않으면 기기 설정을 따릅니다(`scheme.js`, 운영 화면도
같습니다). 운영 화면의 **디자인**에서 **디자인 사용**을 켜면 원본의 기본
디자인(어두운 배경, 왼쪽 메뉴)이 되고, 사이트 이름, 로고, 배경, 글꼴과 색을
정할 수 있습니다. **메뉴**에서 상단 메뉴(2단계까지)를, **메인 슬라이드·인트로**에서
기간이 있는 배너와 첫 방문 인트로를 정합니다. 메뉴를 만들지 않으면 원본의 기본
메뉴(로그, 멤버목록, 신청자목록, 커플목록, 상점, 마이페이지, 퀘스트, 안내)가
보입니다. 메뉴 연결은 `board:게시판ID`, `content:내용페이지ID`,
`tab:members`·`applicants`·`couples`·`shop`·`mypage`·`quests`·`content`, `https://`
주소입니다.

**커뮤니티 설정**에서 상점 분류(쉼표로 구분, 기본 `일반, 이벤트`), 상점 NPC 이미지와
인사말, 배경음악(유튜브 재생목록·영상 주소)을 정합니다. 아이템마다 상점 분류를
고를 수 있습니다. 배경음악은 메뉴 옆 재생 버튼으로 듣고, 페이지를 옮겨 다녀도
이어집니다.

모든 화면에 주소가 있어 링크로 나누고 새로고침해도 그 화면이 열리며, 뒤로 가기도
됩니다: `#/logs/게시판ID/글번호`, `#/character/캐릭터ID`, `#/shop/분류`,
`#/members`, `#/mypage/logs` 등. 캐릭터 이름을 누르면 캐릭터 보기 화면이 열려 큰
그림, 프로필, 능력치, 타이틀, 관계(상대 캐릭터로 이동), 옷장(원본 크기 보기),
경험치 내역을 보여 주고, **커뮤니티 설정**에서 켜면 인벤토리와 오너의 소지금도
보여 줍니다. 소속이 둘 이상이면 멤버목록이 소속별로 나뉘고, 다른 회원의
캐릭터에는 오너에게 쪽지를 보내는 버튼이 있습니다. 상점 아이템은 진열 시작·종료일,
시각, 요일을 정할 수 있고, 그 밖에는 보이지 않고 살 수도 없습니다. 원본처럼
구매는 상점 위에서 고른 **승인된 내 캐릭터**로만 하고, 구매 횟수 제한도
캐릭터마다 셉니다. 세력·종족을 정한 아이템은 고른 캐릭터의 공식 세력·종족에
맞을 때만 목록에 보입니다. 상점은 원본처럼 아이템 그림과 이름을 늘어놓고, 고르면
NPC 대사와 함께 가격(돈 + 소모 경험치 + 교환 아이템), 설명, **효과 설명**과
구매하기 버튼을 보여 줍니다. 구매나 제작에 드는 아이템은 고른 캐릭터의
인벤토리에서 자동으로 꺼냅니다. 인벤토리는 같은 아이템을 한 칸에 개수와 함께,
받은 선물은 따로 표시하고, 칸을 누르면 판매가, 설명, 선물 메시지(By. 보낸
캐릭터)와 판매하기·사용하기·선물하기 버튼이 나옵니다. 버튼은 아이템이 판매
보상이 있고 판매를 허용할 때, 사용 효과가 있고 사용을 허용할 때, 선물을 허용할
때만 보입니다. 선물은 다른 회원의 캐릭터나 내 다른 캐릭터에게 보내고, 다른
회원에게 보내면 원본처럼 도착 쪽지가 갑니다(하루 쪽지 한도에는 세지 않습니다). **상점에서 숨긴**
아이템(경품, 조합 결과 등)은 회원이 SDK로 직접 읽어도 자기 인벤토리에 있거나
볼 수 있는 레시피에 들어 있을 때만 보이고, **숨긴 레시피**는 아무도 읽을 수
없습니다.

로그, 캐릭터, 상점 목록은 원본처럼 번호로 페이지를 넘깁니다(로그·상점 10개,
캐릭터 20개). 페이지 번호가 글 수를 넘으면 원본처럼 빈 목록을 보여 줍니다.
게시판마다 검색창이 있어 모든 글의 제목, 내용, 캐릭터 이름, 닉네임에서
찾습니다(20개씩, 원본 검색처럼 결과마다 300자까지, 더 보면 전체). 게시판 형식에는 그림 로그·일반 글 외에 **질문 답변**
(원본 qna 스킨: 질문을 통째로 보여 주고, 손님도 비밀 질문을 남겨 비밀번호로 다시
열며, 운영진(모더레이터와 사이트 운영자)만 댓글로 답변하고 회원과 손님은 댓글을 달
수 없음)과 **정산**(원본 caculate 스킨: 분류를 골라 캐릭터로
정산을 신청하면 게시물 운영자가 정산완료나 반려로 처리하며 캐릭터 경험치·오너 아보를 지급하고,
처리된 글은 작성자가 고치거나 지울 수 없음)이 있습니다. 정산은 원본처럼 지급
액수에 상한이 없고, 같은 글에 여러 번, 자기 글에도 지급할 수 있습니다. 운영진만
지급하니 운영진은 믿을 수 있는 사람으로 정하세요. 질문 답변 목록은 질문을
통째로 보여 주되, 아주 긴 질문이 여럿이면 한 쪽에 담을 수 있는 만큼만 싣고
나머지는 다음 쪽으로 넘깁니다.

**현재접속자**는 최근 10분 안에 다녀간 회원과 그 위치를 회원에게만 보여 줍니다
(위치에 회원 전용 게시판이 나올 수 있어서입니다). 운영
화면의 **접속자 집계**에서 날짜·시간·요일·월·연도·브라우저·운영체제·기기·접속
경로별 접속 수를(원본처럼 브라우저 하나를 하루에 한 번 셉니다), **활동량 관리**에서 게시판과 기간별로 회원의 로그·댓글 수,
최종 접속, 누적 경고를 봅니다. **소속**과 **종족** 목록을 만들면 캐릭터는 그
가운데서 고르고, 비어 있으면 자유롭게 적습니다. **게시판 그룹**은 게시판
고르기에서 게시판을 묶고, ‘그룹 회원만’을 켜면 회원 등급에서 그 그룹에 넣은
회원과 게시물 운영자만 그 게시판을 씁니다.

**마이페이지**에는 계정정보(운영자가 준 경고가 있으면 **경고내역**도), 내 캐릭터
카드와 대표캐릭터 선택, 로그내역(내가 쓴 로그), **관심로그**(로그의 관심 버튼으로
모은 글, 나만 봄), 경험치 내역, **화폐 관리**(캐릭터 이름으로 상대 오너에게 돈을
보내고, 획득·사용 내역을 봄. 받는 사람에게는 쪽지가 감), 우편함, 호출내역이
있습니다. 우편함은 원본처럼 상대별 대화로 묶여, 마지막 쪽지와 통수, 안 읽은 쪽지
표시(N)를 보여 주고, 열면 주고받은 쪽지를 차례로 보며 그 자리에서 답장합니다. 캐릭터는 원본처럼 마이페이지의 **신규 캐릭터
등록**으로 만들고, 멤버목록과 신청자목록은 목록만 보여 줍니다. 운영 화면의 커뮤니티
설정에서 **캐릭터 생성 가능**, **캐릭터 수정 가능**, **회원당 캐릭터 수**(기본
1명, 0이면 제한 없음)를 정합니다. 수정을 닫아도 승인 전 캐릭터는 신청을 마칠 수
있도록 고칠 수 있습니다. 원본은 설치 직후 생성·수정이 꺼져 있지만, 여기서는 켜진
채로 시작합니다. 원본은 쪽지를 보낼 때마다 자동등록방지
숫자를 입력하게 하는데, 여기서는 대신 회원 한 명이 하루에 보낼 수 있는 쪽지
수(기본 100통)를 운영 화면의 커뮤니티 설정에서 정합니다. 운영자가 캐릭터 경험치를 바꾸면 사유와 함께
회원의 경험치 내역에 남습니다. **탈퇴**하면 이 커뮤니티를 손님으로만 이용하고,
쓴 글과 캐릭터는 남습니다. 운영 화면의 회원 등급에서 탈퇴일을 지우면 다시
이용할 수 있습니다.

## 롤플레이 (캐릭터로 쓰기·탐색·호출)

로그와 댓글을 내 캐릭터로 쓰면 이름, 표시 중인 타이틀, 입은 의상이 함께
남습니다. 주사위는 서버가 굴리고 수정해도 바뀌지 않습니다. 댓글에서
탐색(승인된 캐릭터, 한국 시간 기준 하루 횟수)과 아이템 사용을 할 수 있고,
`[[닉네임]]`으로 회원을 호출합니다. 호출과 내 글의 댓글은 **알림** 탭에
쌓입니다. 캐릭터에는 운영자가 정한 추가 프로필 항목과 수정 중 → 신청 → 승인
상태가 있고, 운영 화면의 **캐릭터 신청 심사**에서 승인합니다. 원본의 관리자
캐릭터 수정처럼 같은 화면에서 어느 회원의 캐릭터든 **수정**(이름, 소속, 종족,
프로필, 이미지, 공개·오너·운영자 전용 추가 항목, 종류, 상태), **삭제**(관계·옷장·
커플·공식 기록을 함께 지우고, 캐릭터에 연결된 아이템은 회원 인벤토리로 돌려놓음),
**회원 변경**(닉네임으로 고른 회원에게 옮기며 옷장·관계·캐릭터의 아이템·공식 기록도
따라감)을 하고, **새 캐릭터**로 회원 대신 캐릭터를 만듭니다. 운영자는 생성·수정
기간과 회원당 캐릭터 수에 묶이지 않습니다. 회원에게 대표 캐릭터가 없으면 새로
받은 캐릭터가 대표가 됩니다. 회원이 처음 만든 캐릭터도 대표가 됩니다. 회원은 승인 전
캐릭터만 삭제할 수 있습니다. 원본의 프로필 양식 관리처럼 **캐릭터 이미지 항목**에서
두상(목록·프로필)·흉상·전신(캐릭터 보기, 입은 의상이 전신을 대신함)을 켜고, 파일로
올릴지 주소로 받을지와 이름·도움말을 정합니다. 처음에는 두상만 켜져 있습니다.
소속·종족에 **선택 가능 회원 등급**을 정하면 그 등급 이상의 회원만 고를 수 있습니다. 승인 전에는
능력치 포인트를 자유롭게 옮길 수 있지만, 승인된 뒤에는 원본처럼 남은 포인트만
배분하고 이미 배분한 능력치는 줄일 수 없습니다.

**커뮤니티 설정**의 하루 탐색 횟수(0이면 탐색 끔), **탐색 표**, 게시판의 **댓글
행동 허용**을 설정합니다.

## 안내 페이지

**내용 페이지**에서 제목, 본문 형식,
기본·모바일 본문, 상단·하단 이미지, 공개 여부와 읽기 등급을 설정합니다.
회원 화면 **안내**에서 선택해 읽습니다. 모바일 본문이 비어 있으면 기본 본문을
표시합니다. 본문은 각각 최대 12,000자입니다.

HTML은 [DOMPurify](https://github.com/cure53/DOMPurify)로 정리하여 표시합니다.
스크립트·폼·전체 페이지에 영향을 주는 스타일/ID/이름은 표시하지 않습니다.
원본의 PHP include와 skin 파일은 내용이나 정적 테마 구성요소로 옮겨야 합니다.
`npm run vendor:content`로 잠긴 의존성에서 배포용 자산을 갱신하고,
`npm run vendor:check`로 자산이 의존성과 일치하는지 검사합니다.

## 코드 둘러보기

기능 하나가 화면 파일 하나와 서버 함수 파일로 나뉘어 있습니다. 화면 쪽은 브라우저에서
그대로 도는 JavaScript 모듈이고, 서버 함수는 나루가 사이트 소유자 권한으로 실행합니다.
돈·재고·주사위처럼 회원이 마음대로 정하면 안 되는 값은 서버 함수만 바꿉니다.

| 기능                   | 화면                                   | 서버 함수                                                        |
| ---------------------- | -------------------------------------- | ---------------------------------------------------------------- |
| 로그인·가입·닉네임     | `app.js`                               | `_naru/functions/community/membership.js`                        |
| 게시판·로그·댓글       | `app/logs.js`, `app/posts.js`          | `_naru/functions/community/posts.js`, `comments.js`, `boards.js` |
| 캐릭터                 | `app/characters.js`                    | `_naru/functions/characters/` (`sheet.js`가 등록·수정·삭제)      |
| 상점·인벤토리·제작     | `app/shop.js`                          | `_naru/functions/economy/`                                       |
| 쪽지                   | `app/messages.js`                      | `_naru/functions/community/messages.js`                          |
| 알림(호출)             | `app/calls.js`                         | `_naru/functions/community/calls.js`                             |
| 퀘스트·안내 페이지     | `app/content.js`                       | `_naru/functions/content/`                                       |
| 디자인·메뉴·배너       | `app/site.js`                          | `_naru/functions/content/site.js`                                |
| 새 글·알림 실시간 수신 | `app/live.js`                          |                                                                  |
| 운영 화면              | `admin/`, `admin.js`, `admin-model.js` | `_naru/functions/characters/review.js`                           |

`app/core.js`는 모든 화면이 함께 쓰는 것(컬렉션 이름, 상태, 오류 표시, 편집 창)입니다.

화면은 컬렉션을 SDK로 직접 읽습니다(`member.collection(...)`, 손님은
`naru.collection(...)`). 누가 무엇을 읽는지는 `_naru/rules/`의 규칙이 정합니다.
쓰기는 서버 함수(`community/posts:write`, `community/comments:write`,
`characters/sheet:save` 등)로 하고, 회원 자신의 프로필(닉네임·알림 설정)만
`rules/profiles.js`가 허락하는 대로 직접 씁니다.

화면은 서버 함수를 `"파일 경로:함수 이름"`으로 부릅니다.

```js
// app/shop.js: 출석 보상 버튼
$("daily").onclick = () =>
  spend(
    "economy/shop:daily",
    null,
    (result) =>
      `출석 보상을 받았습니다. 잔액 ${moneyText(state.names, result.balance)}.`,
  );

function spend(reference, args, success) {
  return run(async () => {
    const result = await state.member.call(reference, args);
    say(success(result));
    await loadShop();
  });
}
```

```js
// _naru/functions/economy/shop.js
export async function daily(ctx) {
  const current = await wallet(ctx);
  const today = kstDay(ctx.now);
  if (current.lastDaily === today)
    ctx.fail("CONFLICT", "오늘은 이미 받았습니다.", { reason: "already" });
  const balance = await pay(ctx, current, -DAILY_REWARD, { lastDaily: today });
  await record(ctx, "daily", { delta: DAILY_REWARD, balance });
  return { balance };
}
```

`ctx.fail`은 호출을 멈추고 그때까지의 쓰기를 모두 되돌립니다. `call`은 그 메시지로
오류를 던지고, `run`이 그 메시지를 화면에 그대로 보여 줍니다. 공통 코드는 `_naru/modules/`에 있고 서버 함수가 정적 import합니다.
번들 생성은 필요하지 않습니다. 자세한 구조는 [_naru/README.md](_naru/README.md)를
참고하세요.
