# 네오 아보카도

[AvocadoEdition](https://github.com/tateck-develop/AvocadoEdition)(그누보드 5 기반
자캐 커뮤니티)을 나루 SDK 1.1.0으로 옮긴 사이트입니다. 원본의 어떤 기능을 어떻게
옮겼는지, 무엇을 옮기지 않았는지는 [docs/porting.md](docs/porting.md)에 있습니다.

## 처음 설치하기

**필요한 것**: 사이트 데이터베이스는 나루 서포터 플랜에 포함되어 있습니다.
회원으로 로그인하는 사람도 서포터 플랜이 있어야 하며, 예외가 필요한 커뮤니티는
나루 운영자에게 문의해 주세요.

1. **사이트에 설치합니다.** 둘 중 하나를 고르세요.
   - 나루 게시판의 네오 아보카도 템플릿에서 **적용하기**를 누르고, 적용할 폴더를
     **사이트 맨 위(루트)**로 고릅니다. 테이블과 서버 코드가 들어 있는 `_naru/` 폴더는
     사이트 맨 위에 있어야 동작하므로, 하위 폴더에 적용하면 회원 기능이 켜지지
     않습니다.
   - 또는 이 저장소를 내 GitHub로 가져가 나루의 GitHub 배포를 사이트 맨 위에
     연결합니다. 이후 푸시할 때마다 사이트가 갱신됩니다.
2. **테이블은 파일과 함께 준비됩니다.** 사이트의 데이터는 모두 테이블이고,
   `_naru/migrations/`가 파일이 올라오는 순간 만듭니다. 컬렉션은 쓰지 않으므로
   운영자 로그인은 아무 권한도 따로 묻지 않습니다. `admin/`(운영 화면)에서 운영자
   로그인을 누릅니다.
3. **가입 방식을 정합니다.** 나루의 데이터베이스 → 사이트 회원에서 누구나 가입,
   운영자 승인 후 이용, 신규 가입 중단 중 하나를 고르고, 필요하면 이메일을
   인증한 계정만 받도록 합니다.
4. **운영 화면에서 커뮤니티를 꾸밉니다.** 게시판(예: 자유, 공지)과 등급,
   캐릭터 추가 항목, 디자인과 메뉴, 안내 페이지를 만듭니다. 원본처럼 처음에는
   게시판이 없으니, 로그를 올릴 게시판부터 만드세요(게시판을 지정하지 않은 글은
   ID `default` 게시판에 속합니다). 사이트 전체 설정은 **커뮤니티 설정** 한 화면에 있습니다.
   운영 화면의 왼쪽 메뉴는 원본처럼 환경설정·회원관리·게시판관리·캐릭터관리·아이템
   관리·기타관리로 묶여 있습니다.

**커뮤니티 설정**의 **회원가입 설정**에 **커뮤니티 활동 규칙**과 **캐릭터
유의사항**을 적으면, 원본의 가입 화면처럼 처음 닉네임을 정하는 회원에게 보여 주고
각각 동의해야 가입합니다(동의한 시각은 회원 기록에 남고, 이미 가입한 회원에게는 묻지
않습니다). **사용할 수 없는 닉네임**(쉼표로 구분, 원본 기본값 admin·관리자·운영자 등)은
가입할 때와 닉네임을 바꿀 때 쓸 수 없고, 사이트 운영자는 쓸 수 있습니다.

화폐(기본 `아보`), 경험치, 랭킹, 소속, 종족의 이름은 원본의 **기타 항목명 설정**처럼
커뮤니티 설정에서 바꿉니다. 바꾼 이름은 사이트와 운영 화면, 서버의 안내 문구에 모두
쓰이고, 소속이나 종족의 이름을 비우면 프로필과 운영 메뉴에서 그 항목이 빠집니다.

개발할 때는:

- 소스는 TypeScript(`.ts`)입니다. `npm run build`가 같은 경로의 JavaScript로
  `dist/`에 만들고, 나루에는 이 `dist/`가 올라갑니다. main에 푸시하면 GitHub
  Actions가 검사한 뒤 `dist/`를 나루의 GitHub Actions 배포로 올립니다
  (`scripts/deploy-naru.mjs`). 나루 배포 설정에 이 저장소와 `refs/heads/main`의
  GitHub Actions 배포 대상이 있어야 합니다.
- 검사: `npm run typecheck`, `npm test`(빌드 후 `dist/`를 검사), `npm run lint`
- 로컬 나루(naru-dev)에서 실제 Chromium으로 전체 흐름:
  `NARU_REPO_PATH=… PLAYWRIGHT_MODULE=… npm run test:e2e`
- 직접 써 보기: `npm run build` 후 나루 저장소의 `control-plane/`에서
  `pnpm naru-dev ~/Git/neo-avocado/dist --site neo-avocado` 후 http://localhost:4000

## 손님과 공개 게시판

그누보드처럼 등급 1은 로그인하지 않은 손님입니다. 게시판의 목록·본문 등급을
1로 두면 누구나 읽고, 글쓰기·댓글 등급을 1로 두면 손님이 이름과 비밀번호로
씁니다. 손님 글은 그 비밀번호로만 고치고 지웁니다. 손님은 비밀글, 캐릭터,
탐색·아이템, 호출, 파일 올리기를 쓸 수 없고 그림은 HTTPS 주소로 넣습니다.
비밀번호는 나루의 `ctx.passwords`가 만든 해시로만 글과 댓글의 행에 보관하고, 어떤
쿼리도 그 해시를 내보내지 않으며, 한 글에 한 시간 열 번까지만 틀릴 수 있습니다. 읽기 등급이 1인 안내 페이지도 공개됩니다(새 안내 페이지와 읽기 등급이 없는
페이지는 원본처럼 1입니다).

**커뮤니티 설정**의 **사이트공개**(원본 `cf_open`)가 켜져 있으면 손님도
멤버목록, 신청자목록, 커플목록과 캐릭터 보기(`/character/캐릭터ID`)를 볼 수 있고,
캐릭터의 추가 항목은 공개 항목만 보입니다. 끄면 손님에게는 인사말과 회원
로그인 카드만 보이고, 게시판·글·캐릭터·닉네임도 쿼리가 읽어 주지 않습니다(원본은
모든 페이지에서 손님을 로그인 페이지로 보냅니다). 원본은 설치 직후 꺼져
있지만, 여기서는 지금까지처럼 손님이 볼 수 있도록 켜진 채로 시작합니다.

## 게시판

로그마다 게시판별 번호(No.)가 붙고, 본문의 `@번호`는 그 로그를, `#태그`는
같은 태그의 로그를 엽니다. 모더레이터는 로그를 공지로 올리거나 다른
게시판으로 옮깁니다. 게시판 설정의 **HTML 본문 허용**을 켜면 최대 12,000자의
HTML 글을 쓰며, 스크립트·폼·스타일은 표시하지 않습니다. 게시판의 **행동 허용**을
켜면 원본처럼 글에서 **탐색**이나 **조합**(재료 1~3개, 레시피와 맞으면 제작,
틀리면 재료만 소모) 가운데 하나와 아이템 사용을, 댓글에서 탐색과 아이템 사용을
합니다. 글의 탐색·조합·아이템은 **승인된 캐릭터**로만, 그 캐릭터가 가진 아이템으로만
합니다. 글과 댓글에서 쓴 아이템은 원본처럼 **뽑기**만 효과가 있고, 나머지(회복약,
프로필 수정권 등)는 사용했다는 기록만 남기고 소모됩니다(사용 후 남기기 아이템은
남음). 효과는 인벤토리에서 써야 납니다. 아직 주사위·행동·아이템이 없는 글은
수정할 때 한 번 더할 수 있습니다. 탐색이나 조합을 기록한 글은 작성자가 지울 수
없고 운영진만 지웁니다(아이템 사용만 한 글은 지울 수 있습니다).

게시판 설명은 원본의 상단 내용처럼 HTML로 보여 줍니다(스크립트 등은 표시하지
않음). 분류가 있는 게시판은 목록 위의 **전체**·분류 링크로 그 분류의 글만 보며,
주소는 `/logs/게시판ID/category/분류`입니다. 게시판 설정에서 원본처럼 다음을
정합니다: **한 페이지 글 수**(기본 15), **로그 자동 접기 높이**(기본 600px),
다른 회원의 댓글이 정한 수(기본 1) 이상 달리면 작성자가 글을 고칠 수 없게 하는
**수정 금지**(0이면 끔, 운영진은 언제나 수정), **새 글 기본 내용**, 글·댓글의
**최소·최대 글자 수**(운영진과 HTML 게시판의 글은 제외), 그리고 회원의 새 글과
댓글에 주는 **글쓰기·댓글쓰기 보상**(커뮤니티 화폐로 주고 내역에 남기며, 지우면
되돌려 받되 잔액이 0 아래로 내려가지는 않음). 원본의 글읽기 포인트는 읽을 때마다
기록을 써야 해서 옮기지 않았습니다. **커뮤니티 설정**의 **단어 필터링**에 쉼표로
적은 단어는 글 제목·본문과 댓글에 쓸 수 없습니다(대소문자 무시, 운영진도 같음).

그림 로그를 쓸 때는 원본 mmb 스킨의 옵션을 고릅니다. **멤버공개**는 손님에게
번호와 표시만 보이고 본문·그림·댓글은 잠기며, **19금**은 빨간 표시와 함께 그림을
가렸다가 누르면 보여 주고, **리플창 아래로**는 댓글을 그림 아래에 두고,
**로그접기**는 그림을 접어 두었다가 OPEN으로 펼칩니다. 게시판의 **로그 자동 접기
높이**보다 큰 그림은 저절로 접힙니다. 게시판에서 **익명 사용**을 켜면 회원은 글과
댓글을 익명으로 쓸 수 있고, 다른 회원과 손님에게는 ‘익명의 누군가’로만
보입니다(작성자 본인과 운영진은 누가 썼는지 봅니다). 멤버공개·19금·익명은
회원만 고릅니다. 운영 화면의 회원 등급에서 **성인**으로 표시한 회원에게는 19금
그림을 가리지 않습니다. 댓글은 여러 줄로 2,000자까지 쓰고, 단 시각이
초까지 붙습니다. 글쓴이가 단 댓글은 글쓴이 색으로, 사이트 운영자가 단 댓글은
**관리자** 표시와 함께 보입니다(익명이면 둘 다 없음).

## 메뉴·디자인·메인 슬라이드

기본 화면은 원본 아보카도 에디션을 설치한 직후(디자인 사용 꺼짐)와 같습니다:
흰 바탕, 왼쪽 위 로고, 가운데 세로 메뉴, 메인의 검은 슬라이드 띠와 회원 카드,
TOP 버튼. 원본과 달리 휴대폰에서는 메뉴가 버튼 뒤로 접히고 상자가 세로로
쌓입니다. 오른쪽 위의 화면 모드(시스템·라이트·다크)로 방문자가 어두운 화면을
고를 수 있고, 고르지 않으면 기기 설정을 따릅니다(`scheme.js`, 운영 화면도
같습니다). 운영 화면의 **디자인**에서 **디자인 사용**을 켜면 원본의 기본
디자인(어두운 배경, 왼쪽 메뉴)이 되고, 사이트 이름, 로고, 배경, 글꼴과 색을
정할 수 있습니다. **메뉴**에서 상단 메뉴(2단계까지)를, **메인 슬라이드·인트로**에서
기간이 있는 배너와 첫 방문 인트로를 정합니다. 메인 슬라이드는 원본처럼 한 장씩
5초마다 넘어가고(마우스나 포커스가 올라가 있으면 멈추고, 이전·다음 버튼이 있으며,
기기에서 동작 줄이기를 켜면 버튼으로만 넘깁니다), 인트로는 메인 화면으로 들어올 때
그림을 한 장씩 보여 주며 누르면 다음 장으로, 마지막 장을 누르면 입장하고 24시간 동안
다시 나오지 않습니다(브라우저 저장소). 디자인에서 모바일 로고·모바일 배경과 배경
색상코드·반복·위치도 정합니다. 메뉴를 만들지 않으면 원본의 기본
메뉴(로그, 멤버목록, 신청자목록, 커플목록, 상점, 마이페이지, 퀘스트, 안내)가
보입니다. 메뉴 연결은 `board:게시판ID`, `content:내용페이지ID`,
`tab:members`·`applicants`·`couples`·`shop`·`mypage`·`quests`·`content`, `https://`
주소입니다.

**커뮤니티 설정**에서 상점 분류(쉼표로 구분, 기본 `일반, 이벤트`), 상점 NPC 이미지와
인사말, 배경음악(유튜브 재생목록·영상 주소)을 정합니다. 아이템마다 상점 분류를
고를 수 있습니다. 배경음악은 메뉴 옆 재생 버튼으로 듣고, 페이지를 옮겨 다녀도
이어집니다.

같은 설정의 **화폐**에서 원본처럼 **로그인 시 획득**(한국 시간으로 하루의 첫
방문에 자동 지급, 출석 버튼은 없음)과 **회원가입 시 획득**(처음 가입할 때 한 번)을
정합니다. 원본처럼 둘 다 0으로 시작하므로, 운영자가 정하기 전에는 매일 받는 보상이
없습니다. 원본의 화폐기능 사용(끄기) 스위치는 옮기지 않았습니다.

상점은 원본의 아이템 관리와 상점 관리를 합친 것입니다. 아이템은 **상점에서
숨기기**를 끄면 상점에 진열되므로, 새 아이템은 가격 0으로 팔리지 않게 숨긴 채
시작합니다. 상점은 아이템의 **진열 순서**(작은 수가 먼저), 그다음 이름 순입니다.

모든 화면에 주소가 있어 링크로 나누고 새로고침해도 그 화면이 열리며, 뒤로 가기도
됩니다: `/logs/게시판ID/글번호`, `/post/글ID`, `/character/캐릭터ID`, `/shop/분류`,
`/members`, `/mypage/logs` 등. 예전의 `#/logs/…` 꼴 주소(즐겨찾기, 글 속 링크)도
열리며, 열리는 즉시 `/logs/…` 꼴로 바뀝니다. 캐릭터 이름을 누르면 캐릭터 보기 화면이 열려 큰
그림, 프로필, 능력치, 타이틀, 관계(승인된 캐릭터만. 호감도 0~5 하트, 한 줄에 하나씩
적은 여러 관계 링크, 관계 요약이 빈 관계는 숨김, 상대 캐릭터로 이동), 옷장(전신을
쓸 때만. 원본 크기 보기, 이름·주소 수정), 경험치 내역(20개씩, 더 보기)을 보여 주고, **커뮤니티 설정**에서 켜면 인벤토리와 오너의 소지금도
보여 줍니다. 소속이 둘 이상이면 멤버목록이 소속별로 나뉘고, 다른 회원의
캐릭터에는 오너에게 쪽지를 보내는 버튼이 있습니다. 상점 아이템은 진열 시작·종료일,
시각, 요일을 정할 수 있고, 그 밖에는 보이지 않고 살 수도 없습니다. 원본처럼
구매는 상점 위에서 고른 **승인된 내 캐릭터**로만 하고, 구매 횟수 제한도
캐릭터마다 셉니다. 세력·종족을 정한 아이템은 고른 캐릭터가 시트에 고른 소속·종족에
맞을 때만 목록에 보이고 살 수 있습니다(사용 조건도 같습니다). 상점은 원본처럼 아이템 그림과 이름을 늘어놓고, 고르면
NPC 대사와 함께 가격(돈 + 소모 경험치 + 교환 아이템), 설명, **효과 설명**과
구매하기 버튼을 보여 줍니다. 구매나 제작에 드는 아이템은 고른 캐릭터의
인벤토리에서 자동으로 꺼냅니다. 인벤토리는 같은 아이템을 한 칸에 개수와 함께,
받은 선물은 따로 표시하고, 칸을 누르면 판매가, 설명, 선물 메시지(By. 보낸
캐릭터)와 판매하기·사용하기·선물하기 버튼이 나옵니다. 버튼은 아이템이 판매
보상이 있고 판매를 허용할 때, 사용 효과가 있고 사용을 허용할 때, 선물을 허용할
때만 보입니다. 선물은 다른 회원의 캐릭터나 내 다른 캐릭터에게 보내고, 다른
회원에게 보내면 원본처럼 도착 쪽지가 갑니다(하루 쪽지 한도에는 세지 않습니다).
**프로필 수정** 아이템을 사용하면 원본처럼 그 캐릭터의 전체 수정 화면이 열리고
(수정 기간이 아니어도 승인된 캐릭터를 고칠 수 있음), 저장할 때 아이템이 소모됩니다
(계속 사용 가능한 아이템은 남음). **상점에서 숨긴**
아이템(경품, 조합 결과 등)은 회원이 SDK로 직접 읽어도 자기 인벤토리에 있거나
볼 수 있는 레시피에 들어 있을 때만 보이고, **숨긴 레시피**는 아무도 읽을 수
없습니다.

로그, 캐릭터, 상점 목록은 원본처럼 번호로 페이지를 넘깁니다(로그는 게시판의 한
페이지 글 수, 기본 15개(질문 답변은 10개까지), 상점 10개, 캐릭터 20개). 페이지
번호가 글 수를 넘으면 원본처럼 빈 목록을 보여 줍니다.
게시판마다 검색창이 있어 모든 글의 제목, 내용, 캐릭터 이름, 닉네임에서 찾고,
원본처럼 댓글 내용과 댓글 쓴이(닉네임·캐릭터 이름)에서도 찾아 그 댓글이 달린 글을
뒤이어 보여 줍니다(20개씩, 원본 검색처럼 결과마다 300자까지, 더 보면 전체). 게시판 형식에는 그림 로그·일반 글 외에 **질문 답변**
(원본 qna 스킨: 질문을 통째로 보여 주고, 손님도 비밀 질문을 남겨 비밀번호로 다시
열며, 운영진(모더레이터와 사이트 운영자)만 댓글로 답변하고 회원과 손님은 댓글을 달
수 없음)과 **정산**(원본 caculate 스킨: 분류를 골라 캐릭터로
정산을 신청하면 게시물 운영자가 정산완료나 반려로 처리하며 캐릭터 경험치·오너 아보를 지급하고,
처리된 글은 작성자가 고치거나 지울 수 없음)이 있습니다. 정산은 원본처럼 지급
액수에 상한이 없고, 같은 글에 여러 번, 자기 글에도 지급할 수 있습니다. 운영진만
지급하니 운영진은 믿을 수 있는 사람으로 정하세요. 질문 답변 목록은 질문을
통째로 보여 주되, 아주 긴 질문이 여럿이면 한 쪽에 담을 수 있는 만큼만 싣고
나머지는 다음 쪽으로 넘깁니다.

**현재접속자**는 최근 10분 안에 다녀간 회원과 그 위치를 회원에게만 보여 줍니다
(위치에 회원 전용 게시판이 나올 수 있어서입니다). 운영
화면의 **접속자 집계**에서 날짜·시간·요일·월·연도·브라우저·운영체제·기기·접속
경로별 접속 수를(원본처럼 브라우저 하나를 하루에 한 번 셉니다), **활동량 관리**에서 게시판과 기간별로 회원의 로그·댓글 수,
최종 접속, 누적 경고를 봅니다. **회원 등급·운영 역할** 목록은 원본의 회원관리처럼
회원마다 등급, 역할, 경고, 탈퇴일, 최종 접속을 보여 주고 닉네임이나 회원 번호로
찾습니다. **소속**과 **종족** 목록을 만들면 캐릭터는 그
가운데서 고르고, 비어 있으면 자유롭게 적습니다. **게시판 그룹**은 게시판
고르기에서 게시판을 묶고, ‘그룹 회원만’을 켜면 회원 등급에서 그 그룹에 넣은
회원과 게시물 운영자만 그 게시판을 씁니다.

**마이페이지**에는 계정정보(운영자가 준 경고가 있으면 **경고내역**도), 내 캐릭터
카드(프로필 기본 항목에서 켜 둔 랭킹·경험치도)와 대표캐릭터 선택, 로그내역(내가 쓴 로그), **관심로그**(로그의 관심 버튼으로
모은 글, 나만 봄), 경험치 내역, **화폐 관리**(캐릭터 이름으로 상대 오너에게 돈을
보내고, 획득·사용 내역을 봄. 받는 사람에게는 쪽지가 감), 우편함, 호출내역이
있습니다. 계정정보에는 가입일(처음 닉네임을 정한 날)도 보입니다. 우편함은 원본처럼
상대별 대화로 묶여, 마지막 쪽지와 통수, 안 읽은 쪽지 표시(N)를 보여 주고, 열면
주고받은 쪽지를 최근 50통부터 차례로 보며(**이전 쪽지 더 보기**로 그 전 50통씩) 그
자리에서 답장합니다. 상대 목록은 주고받은 쪽지 전부를 상대별로 묶어 만듭니다. 안 읽은
쪽지와 새 알림은 새로고침 없이 바로 표시됩니다. 메인 화면의 회원 카드는 원본처럼 안 읽은
쪽지 수, 캐릭터가 없으면 **캐릭터 생성** 버튼(생성 기간이 아니면 그렇다는 안내),
사이트 운영자에게는 **관리자** 링크를 보여 줍니다. 캐릭터는 원본처럼 마이페이지의 **신규 캐릭터
등록**으로 만들고, 멤버목록과 신청자목록은 목록만 보여 줍니다. 멤버목록은 원본처럼
먼저 승인된 캐릭터부터(소속이 둘 이상이면 소속별로), 신청자목록은 최근 신청부터 10명씩
보여 주며 ALL과 소속·종족별 인원으로 거르고 오너명이나 캐릭명으로 찾습니다. 운영
화면의 **프로필 기본 항목**에서 캐릭터 보기에 경험치·랭킹·능력치·타이틀·옷장을
보일지 정하고(옷장은 전신을 쓸 때만 보이고, 의상은 두상을 대신하지 않음), 커플목록은
사귄 날짜와 함께 D+일수를 보여 주며 이름을 누르면 캐릭터 보기로 가고, 현재접속자는 사이트 운영자를
빼고 보여 줍니다. 운영 화면의 커뮤니티
설정에서 **캐릭터 생성 가능**, **캐릭터 수정 가능**, **회원당 캐릭터 수**(기본
1명, 0이면 제한 없음)를 정합니다. 수정을 닫아도 승인 전 캐릭터는 신청을 마칠 수
있도록 고칠 수 있습니다. 원본은 설치 직후 생성·수정이 꺼져 있지만, 여기서는 켜진
채로 시작합니다. 원본은 쪽지를 보낼 때마다 자동등록방지
숫자를 입력하게 하는데, 여기서는 대신 회원 한 명이 하루에 보낼 수 있는 쪽지
수(기본 100통)를 운영 화면의 커뮤니티 설정에서 정합니다. 운영자가 캐릭터 경험치를 바꾸면 사유와 함께
회원의 경험치 내역에 남습니다. **탈퇴**하면 이 커뮤니티를 손님으로만 이용하고,
쓴 글과 캐릭터는 남습니다. 운영 화면의 회원 등급에서 탈퇴일을 지우면 다시
이용할 수 있습니다.

## 롤플레이 (캐릭터로 쓰기·탐색·호출)

로그와 댓글을 내 캐릭터로 쓰면 이름, 표시 중인 타이틀, 입은 의상이 함께
남습니다. 주사위는 서버가 굴리고 수정해도 바뀌지 않습니다. 댓글에서
탐색(승인된 캐릭터, 한국 시간 기준 하루 횟수)과 아이템 사용을 할 수 있고,
`[[닉네임]]`으로 회원을 호출합니다(한 글에 10명까지: 호출마다 알림을 기록하는데 한 번에 쓸 수 있는 양이 정해져 있어서). 호출과 내 글의 댓글은 **알림** 탭에
쌓입니다. 캐릭터에는 운영자가 정한 추가 프로필 항목과 수정 중 → 신청 → 승인
상태가 있고, 운영 화면의 **캐릭터 신청 심사**에서 승인합니다. 심사 목록은 캐릭터
이름이나 오너 닉네임으로 찾고, 소속·종족과 상태(상태별 인원 수)로 거르며, 체크한
캐릭터를 **선택 승인**으로 한 번에 승인합니다. 메인·서브·NPC 종류는 원본처럼
운영자만 정하고, 회원이 만든 캐릭터는 메인으로 시작합니다. 추가 항목에 **단위**를
적으면(예: cm) 한 줄 텍스트 입력칸과 값 뒤에 붙고, **사용**을 끈 타이틀은 어디에도
보이지 않습니다. 원본의 관리자
캐릭터 수정처럼 같은 화면에서 어느 회원의 캐릭터든 **수정**(이름, 소속, 종족,
프로필, 이미지, 공개·오너·운영자 전용 추가 항목, 종류, 상태), **삭제**(관계·옷장·
커플·공식 기록을 함께 지우고, 캐릭터에 연결된 아이템은 회원 인벤토리로 돌려놓음),
**회원 변경**(닉네임으로 고른 회원에게 옮기며 옷장·관계·캐릭터의 아이템·공식 기록도
따라감)을 하고, **새 캐릭터**로 회원 대신 캐릭터를 만듭니다. 운영자는 생성·수정
기간과 회원당 캐릭터 수에 묶이지 않습니다. 회원에게 대표 캐릭터가 없으면 새로
받은 캐릭터가 대표가 됩니다. 회원이 처음 만든 캐릭터도 대표가 됩니다. 대표
캐릭터를 삭제하거나 다른 회원에게 옮기면 남은 캐릭터 가운데 가장 먼저 만든 것이
대표가 됩니다. 회원은 승인 전
캐릭터만 삭제할 수 있습니다. 원본의 프로필 양식 관리처럼 **캐릭터 이미지 항목**에서
두상(목록·프로필)·흉상·전신(캐릭터 보기, 입은 의상이 전신을 대신함)을 켜고, 파일로
올릴지 주소로 받을지와 이름·도움말을 정합니다. 처음에는 두상만 켜져 있습니다.
소속·종족에 **선택 가능 회원 등급**을 정하면 그 등급 이상의 회원만 고를 수 있습니다. 승인 전에는
능력치 포인트를 자유롭게 옮길 수 있지만, 승인된 뒤에는 원본처럼 남은 포인트만
배분하고 이미 배분한 능력치는 줄일 수 없습니다.

**커뮤니티 설정**의 하루 탐색 횟수(0이면 탐색 끔), **탐색 표**, 게시판의 **댓글
행동 허용**을 설정합니다. 원본은 하루 횟수를 넘긴 탐색 댓글을 탐색 없이 올리지만,
여기서는 댓글을 올리지 않고 횟수를 다 썼다고 알립니다. 탐색 표와 뽑기 표는 원본의
0~100 구간 대신 **무게**를 씁니다: 원본에서 0~30, 31~100이던 두 줄은 무게 30과
70처럼 구간의 너비를 무게로 옮기면 같은 확률이 됩니다.

## 안내 페이지

**내용 페이지**에서 제목, 본문 형식,
기본·모바일 본문, 상단·하단 이미지, 공개 여부와 읽기 등급을 설정합니다.
회원 화면 **안내**에서 선택해 읽습니다. 모바일 본문이 비어 있으면 기본 본문을
표시합니다. 본문은 각각 최대 12,000자입니다. 읽기 등급은 기본 1(손님도 읽음)입니다.
ID가 `site_main`인 내용 페이지는 원본의 **메인화면 구성**처럼 메인 화면의 기본 배너
자리에 보이고, 안내 목록에는 나오지 않습니다. 그 본문의 치환 문구는 원본처럼
바뀝니다: `{{VISUAL_SLIDE}}`는 메인 슬라이드, `{{OUTLOGIN}}`은 회원 카드,
`{{LOGIN}}`·`{{JOIN}}`은 손님에게 보이는 로그인 링크(가입은 나루 로그인에서 합니다),
`{{LOGOUT}}`·`{{MYPAGE}}`는 회원에게 보이는 로그아웃·마이페이지 링크가 되고,
`{{BGM}}`(배경음악은 상단 버튼)과 `{{TWITTER}}`(타임라인 위젯은 더 이상 동작하지
않음)는 지워지며, 그 밖의 문구는 그대로 둡니다. 본문을 정리한 뒤 사이트의 요소로
바꾸므로 스크립트가 끼어들 수 없습니다.

운영 화면의 **디자인**에서 사이트 설명과 파비콘을(열려 있는 탭에 적용), **아이템
관리 → 아보·경험치·아이템 지급**에서 회원 한 명이나 전체 회원(원본처럼 등급 1
회원 제외)에게 아보를, 캐릭터 하나나 승인된 전체 캐릭터에게 경험치를 내용과 함께
주거나 깎고, 아이템을 1~100개 줍니다(최근 지급 기록이 함께 보임). **랭킹 설정**의 단계마다 달성 시 추가 능력치 포인트를 정하면, 경험치로
단계가 오를 때 그만큼 받고 내려가면 돌려놓습니다. 아이템마다 **로그·댓글에서 사용
가능**과 **조합 재료로 사용 가능**을, 능력치마다 **최소값**과 **도움말**을 정합니다.
둘 다 원본처럼 꺼진 채 시작하고, 켠 아이템만 글에서 쓰거나 조합·제작 재료로
넣을 수 있습니다. 이 설정이 생기기 전에 만든 아이템은 꺼진 것으로 보니, 쓰던
아이템이면 켜 주세요. 레시피에는 조합 재료로 쓸 수 있는 아이템만 넣을 수 있고,
다른 레시피와 같은 재료 조합은 저장되지 않습니다. 제작에 쓴 재료 중 **사용 후
남기기**인 것은 남습니다. 회복 아이템은 이미 가득 찼어도 원본처럼 사용되어
소모됩니다.

**링크 미리보기**: 메신저나 SNS가 링크 미리보기를 만들 때 읽는 제목, 설명과
`og:`·`twitter:` 태그(원본 `cf_site_descript`, `cf_site_img`)는 나루의 라우트
(`_naru/routes/`)가 주소마다 `index.html`의 `<head>`에 넣습니다. 글 주소는 그 글의
제목, 첫 부분, 그림(없으면 말한 캐릭터의 두상)을, 캐릭터 주소는 이름, 프로필,
그림을, 게시판 주소는 이름과 설명을, 안내 페이지는 제목을 보여 줍니다. 손님이
읽을 수 없는 것(비밀글, 멤버공개·19금 글, 손님에게 닫힌 게시판과 페이지, 사이트공개를
끈 사이트의 모든 주소)은 사이트의 미리보기만 보여 줍니다. 사이트의 이름, 설명,
**대표 이미지**(빈칸이면 로고)와 **사이트 주소**는 운영 화면의 **디자인**에서
정합니다. 나루는 라우트에 주소의 경로만 알려 주므로, 사이트 주소를 적어야
`og:url`과 `canonical`이 `https://…`로 시작하는 온전한 주소가 됩니다. 미리보기는
나루에서 1분 동안 보관됩니다.

**원본과 일부러 다르게 한 것**

- 쪽지 삭제는 내 보관함에서만 지워지고 상대의 보관함에는 남습니다.
- 쪽지는 운영자가 정한 비용이 들고, 하루 보낼 수 있는 수가 정해져 있으며, 쪽지를 받지
  않도록 설정할 수 있습니다.
- 메뉴는 HTML을 직접 쓰지 않고 이름·연결·순서로 만듭니다.
- 배경음악은 자동 재생하지 않고 재생 버튼을 눌러야 나옵니다.
- 운영자의 추가 스크립트·메타 태그(`cf_add_script`, `cf_add_meta`)는 안전을 위해
  지원하지 않습니다.

HTML은 [DOMPurify](https://github.com/cure53/DOMPurify)로 정리하여 표시합니다.
스크립트·폼·전체 페이지에 영향을 주는 스타일/ID/이름은 표시하지 않습니다.
원본의 PHP include와 skin 파일은 내용이나 정적 테마 구성요소로 옮겨야 합니다.
`npm run vendor:content`로 잠긴 의존성에서 배포용 자산을 갱신하고,
`npm run vendor:check`로 자산이 의존성과 일치하는지 검사합니다.

## 코드 둘러보기

기능 하나가 화면 파일과 서버 코드(쿼리·뮤테이션)로 나뉘어 있습니다. 둘 다 TypeScript로
쓰고 같은 경로의 JavaScript로 빌드합니다(아래 표의 `.js`는 빌드 결과, 소스는 같은
이름의 `.ts`). 화면 쪽은 브라우저에서 도는 모듈이고, 쿼리(`_naru/queries/`, 읽기만)와
뮤테이션(`_naru/mutations/`, 한 번의 트랜잭션)은 나루에서 사이트의 테이블에 SQL을
실행합니다. 누구나 부를 수 있으므로 코드가 부른 사람(`ctx.member`, `ctx.owner`,
`ctx.visitor`)을 보고 무엇을 읽고 쓸지 정합니다.
돈·재고·주사위처럼 회원이 마음대로 정하면 안 되는 값은 뮤테이션만 바꿉니다.

| 기능                   | 화면                                   | 서버 코드                                                          |
| ---------------------- | -------------------------------------- | ------------------------------------------------------------------ |
| 로그인·가입·닉네임     | `app.js`                               | `_naru/queries/community/`, `_naru/mutations/community/`           |
| 게시판·로그·댓글       | `app/logs.js`, `app/posts.js`          | `_naru/queries/community/`, `_naru/mutations/community/`           |
| 캐릭터                 | `app/characters.js`, `app/couples.js`  | `_naru/queries/characters/`, `_naru/mutations/characters/`         |
| 상점·인벤토리·제작     | `app/shop.js`                          | `_naru/queries/economy/`, `_naru/mutations/economy/`               |
| 쪽지                   | `app/messages.js`                      | `_naru/queries/community/messages.js`, `mutations/community/`      |
| 알림(호출)             | `app/calls.js`                         | `_naru/queries/community/calls.js`, `mutations/community/calls.js` |
| 퀘스트·안내 페이지     | `app/content.js`                       | `_naru/queries/content/`                                           |
| 디자인·메뉴·배너       | `app/site.js`                          | `_naru/queries/content/site.js`                                    |
| 새 글·알림 실시간 수신 | `app/live.js`                          | `_naru/queries/community/inbox.js`, `posts.js`                     |
| 운영 화면              | `admin/`, `admin.js`, `admin-model.js` | `_naru/queries/admin/`, `_naru/mutations/admin/`                   |

`app/core.js`는 모든 화면이 함께 쓰는 것(상태, 오류 표시, 편집 창)입니다.

모든 기능이 `_naru/migrations/`의 테이블을 쓰고, 화면은 `query`·`mutate`·`subscribe`
(`app/core.js`)로 `_naru/queries/`·`_naru/mutations/`를 부릅니다(`docs/port.md`).
누가 무엇을 읽고 쓰는지는 그 코드가 정합니다(게시판은 `_naru/modules/boards.js`).
새 쪽지와 알림은 `community/inbox:status`를 구독해 받습니다: 나루는 쪽지·호출을 쓰는
mutation이 끝날 때마다 그 답을 다시 보내 줍니다.

운영 화면은 섹션마다 운영자만 부를 수 있는 쿼리·뮤테이션(`admin/boards:save`,
`admin/members:list` 등)을 씁니다. 저장은 양식에 적은 값을 그대로 보내고, 서버가
양식과 같은 규칙(`_naru/modules/admin-model.js`)으로 검사한 뒤 테이블에 씁니다.
잔액과 그 조정 기록, 경험치와 그 기록, 여러 캐릭터의 타이틀 지급·회수는 각각 한 번의
뮤테이션입니다.

화면은 쿼리와 뮤테이션을 `"파일 경로:함수 이름"`으로 부릅니다.

```js
// app/shop.js: 뽑기 버튼
$("gacha").onclick = () =>
  spend(
    "economy/shop:gacha",
    state.inventoryCharacter ? { character: state.inventoryCharacter } : null,
    (result) =>
      result.owned
        ? `뽑기에서 ${result.owned.data.name}이(가) 나왔습니다!`
        : "아무것도 나오지 않았습니다.",
  );

function spend(reference, args, success) {
  return run(async () => {
    const result = await mutate(reference, args);
    say(success(result));
    await loadShop();
  });
}
```

```js
// _naru/mutations/economy/shop.js (줄임)
export async function gacha(ctx, args) {
  signedIn(ctx);
  const { character = null } = args ?? {};
  const current = await wallet(ctx);
  if (current.balance < GACHA_COST)
    ctx.fail("CONFLICT", await lacking(ctx, "moneyName"), {
      reason: "not_enough",
    });
  const result = await draw(ctx);
  if (!result.configured)
    ctx.fail("CONFLICT", "아직 뽑을 것이 없습니다.", { reason: "empty" });
  const balance = await pay(ctx, current, GACHA_COST);
  const owned = result.prize
    ? await give(ctx, result.prize, "gacha", character)
    : null;
  return { balance, owned };
}
```

`ctx.fail`은 호출을 멈추고 그때까지의 쓰기를 모두 되돌립니다. `mutate`는 그 메시지로
오류를 던지고, `run`이 그 메시지를 화면에 그대로 보여 줍니다. 공통 코드는 `_naru/modules/`에 있고 쿼리와 뮤테이션이 정적 import합니다.
번들 생성은 필요하지 않습니다. 자세한 구조는 [_naru/README.md](_naru/README.md)를
참고하세요.
